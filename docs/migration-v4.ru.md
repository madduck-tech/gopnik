# Переход на Gopnik 4

Cerberus переименован в Gopnik. В версии 4 меняются репозиторий, плагин, навыки,
вспомогательный скрипт, конфигурация и переменные окружения. Это смена идентичности,
а не обычное обновление плагина на месте.

## Безопасный порядок

1. Выполните текущую [инструкцию по установке](install.md) и убедитесь, что агент
   видит `gopnik`, `gopnik-critic` и `gopnik-setup`.
2. Найдите старый плагин, локальные каталоги навыков и конфигурацию, ничего не удаляя.
3. Перенесите ровно одну корректную конфигурацию в соответствующий новый путь.
4. Снова проверьте Gopnik.
5. Удалите только найденные старые цели.

Не объединяйте две конфигурации автоматически. Если старый и новый файлы
существуют одновременно, сравните их и спросите оператора, какой из них основной.

## Карта идентификаторов

| До версии 4.0 | Gopnik 4 |
| --- | --- |
| `cerberus@concordloom` | `gopnik@madduck-tech` |
| `cerberus`, `cerberus-critic`, `cerberus-setup` | `gopnik`, `gopnik-critic`, `gopnik-setup` |
| `cerberus_setup.py` | `gopnik_setup.py` |
| `cerberus.json` | `gopnik.json` |
| `.claude/cerberus.json` | `.claude/gopnik.json` |
| `.codex/cerberus.json` | `.codex/gopnik.json` |
| `CERBERUS_*` | `GOPNIK_*` |

Если меняется только путь, сохраните содержимое конфигурации без изменений.
Для отслеживаемого файла сначала подтвердите переименование в репозитории.

## Удаление старой установки

Только после проверки Gopnik удалите старый штатный плагин по точному
идентификатору хоста или удалите точные локальные каталоги старых навыков. Не
удаляйте целиком `.claude/skills` или `.agents/skills`; если цель — символическая
ссылка, удалите только ссылку.

Конфигурация хранит знания о проекте. Удаляйте её только после отдельного
подтверждения оператора и проверки соответствующего файла Gopnik.
